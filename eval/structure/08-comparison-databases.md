사이드 프로젝트용 데이터베이스로 PostgreSQL, MySQL, SQLite를 고민 중이시군요. 기준별로 비교해 보겠습니다.

**PostgreSQL**
- 동시성: MVCC 기반이라 읽기와 쓰기가 서로 거의 막지 않습니다.
- 확장성: 읽기 복제본과 파티셔닝으로 대규모 서비스까지 확장할 수 있습니다.
- 운영 난이도: 별도 서버 프로세스가 필요하고, VACUUM 등 튜닝 포인트가 있어 중간 수준입니다.
- JSON 지원: JSONB 타입과 GIN 인덱스로 문서형 데이터도 잘 다룹니다.
- 적합한 용도: 복잡한 쿼리와 데이터 무결성이 중요한 서비스

**MySQL**
- 동시성: InnoDB 엔진의 행 단위 잠금으로 일반적인 웹 서비스 부하는 충분히 처리합니다.
- 확장성: 복제 구성이 성숙해 있고 관리형 서비스 선택지가 많습니다.
- 운영 난이도: 자료와 운영 경험이 풍부해 비교적 쉬운 편입니다.
- JSON 지원: JSON 타입은 있지만 인덱싱은 생성 컬럼을 거쳐야 해 PostgreSQL보다 불편합니다.
- 적합한 용도: 읽기 비중이 큰 일반 웹 서비스

**SQLite**
- 동시성: 쓰기는 한 번에 하나만 가능합니다(WAL 모드에서도 쓰기는 직렬).
- 확장성: 단일 파일이라 서버를 여러 대로 늘리는 구조에는 맞지 않습니다.
- 운영 난이도: 서버가 없고 파일 하나라 가장 쉽습니다.
- JSON 지원: JSON1 확장 함수로 기본적인 조회는 가능합니다.
- 적합한 용도: 모바일 앱, 데스크톱 앱, 프로토타입

**한 줄 추천**: 혼자 빠르게 프로토타입을 만든다면 SQLite로 시작하고, 사용자가 늘어날 계획이라면 처음부터 PostgreSQL을 쓰는 편이 이전 비용을 줄입니다.
