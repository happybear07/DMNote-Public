# ADR-0001: 캔버스 엔진을 직접 만든다

| 항목 | 내용 |
|---|---|
| 상태 | 승인 |
| 날짜 | 2026-09-30 |
| 결정자 | 곰탱이 (제안: 설계 문서 작성 시) |

## 맥락

노션의 적층형 블록 구조는 위치가 곧 순서라 자유 배치가 불가능하다. 기존 화이트보드 라이브러리(tldraw · Excalidraw · Konva 등)는 자유 배치는 되지만 "블록 안 콘텐츠의 순서(order)", 잉크 묶기, AI 결과의 단일 트랜잭션 적용, 1만 블록 성능 예산을 동시에 만족하지 않는다. 제품의 차별점이 캔버스 자체에 있다.

## 결정

씬 그래프 · 좌표계 · 배치 · 히트테스트 · 잉크 · 트랜잭션을 소유하는 엔진을 직접 만든다. 텍스트 편집 코어(ProseMirror), 공간 인덱스(rbush), 외곽선(perfect-freehand), 순서 키(fractional-indexing), 동기화(Yjs)는 빌려 쓴다.

## 결과

- 엔진 개발이 일정의 최대 리스크가 된다 (ENGINE 17~20주 추정 vs 한 달 계획 1주).
- 제품 고유 규칙(order · 잉크 3상태 · 단일 undo)을 엔진 수준에서 보장할 수 있다.
- 헤드리스 코어를 테스트로 먼저 검증해 이후 기능의 회귀를 줄인다.

## 검토한 대안

- tldraw SDK 위에 구축 — 라이선스 · 블록 내부 순서 모델 부재
- Excalidraw 포크 — 도형 중심 모델, 리치 텍스트 블록 부적합
- 노션식 적층 구조 유지 — 제품 차별점 상실
