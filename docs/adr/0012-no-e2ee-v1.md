# ADR-0012: v1은 종단간 암호화 없이 전송 · 저장 암호화만

| 항목 | 내용 |
|---|---|
| 상태 | 승인 (2026-10-01, 설계 마무리 위임에 따라 추천안 채택) |
| 날짜 | 2026-10-01 |
| 결정자 | 곰탱이 (제안: 설계 문서 작성 시) |

## 맥락

FR-146은 E2EE 범위를 아키텍처 단계에서 정하라고 한다. E2EE는 서버 측 공유 링크 렌더(FR-134), 서버 측 처리, 키 분실 시 복구와 충돌하고, 한 달 일정에 키 관리 UX까지 넣기 어렵다.

## 결정

v1은 TLS 전송 암호화와 플랫폼 저장 암호화만 쓴다. 서버는 노트 내용을 해석하지 않는 구조(불투명 Yjs 업데이트 · 클라이언트 검색)를 유지해 이후 E2EE 도입 비용을 낮춘다. 노트 잠금(FR-144)은 해당 노트만 클라이언트 암호화한다.

## 결과

- 운영자 · 플랫폼 침해 시 노트 내용이 노출될 수 있다 — 개인정보 고지에 명시한다.
- E2EE 도입 시 바뀌는 곳은 sync-yjs(업데이트 암호화)와 공유 링크 렌더 방식이다.

## 검토한 대안

- v1부터 E2EE — 일정 · 복구 UX · 공유 기능 충돌
