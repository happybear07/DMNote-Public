# ADR-0013: 텍스트 상자 두 종류 (제목 상자 · 내용 상자)

| 항목 | 내용 |
|---|---|
| 상태 | 승인 (2026-10-02, 사용자 결정) |
| 날짜 | 2026-10-02 |
| 결정자 | 곰탱이 |

## 맥락

스키마 v1의 텍스트 블록은 텍스트 콘텐츠 하나에 제목(heading) 줄과 본문 문단이 한 문서로 섞여 있었다. 10/02 오전에 한 블록 안에 제목 칸과 본문 칸을 나눈 v2를 만들었으나, 사용자는 "제목 상자에서는 제목만, 내용 상자에서는 내용만" 쓰는 쪽을 택하고 v2를 쓰지 않기로 했다. 캔버스에서 큰 제목을 따로 놓고 그 아래·옆에 내용 카드를 배치하는 쓰임이 자유 배치(ADR-0014)와도 잘 맞는다.

## 결정

텍스트 블록은 **텍스트 콘텐츠 하나**를 갖고, 그 역할(`TextContent.role`)이 상자 종류다 (스키마 v3).

- **제목 상자** (`role: 'title'`): 문서는 문단 하나뿐인 한 줄 제목 — 엔진 불변식 I10이 커밋마다 확인한다. 크고 굵은 한 줄, 테두리 없는 카드. T 도구로 만든다. Enter · Tab은 편집 끝, 여러 줄 붙여넣기는 한 줄로 합침, 마크다운 입력 규칙 꺼짐, 서식 툴바는 글자 서식만.
- **내용 상자** (`role: 'body'`, 없으면 body로 읽음): 리치 텍스트 문서(ENGINE D8 그대로). B 도구 · 빈 캔버스 더블클릭 · 붙여넣기 · 블록으로 분리로 만든다.
- 서로 바꾸기는 블록 메뉴 "상자 종류"(`convertBoxes`). 내용 → 제목은 글자를 한 줄로 펴며 글자 서식은 남는다. 다중 선택도 undo 한 번.
- AI 노드는 본문이 없으면 제목 상자, 있으면 내용 상자.
- 마이그레이션: v1 → v2(첫 heading을 제목 칸으로) → v3(한 블록의 제목 칸 + 본문 칸을 상자 하나로: 본문이 비면 제목 상자, 제목이 비면 내용 상자, 둘 다 있으면 제목을 맨 앞 제목3 줄로 합친 내용 상자). 본문 콘텐츠 id를 유지해 AI 출처 참조가 끊기지 않는다.

## 결과

- 블록 하나의 텍스트 = 문서 하나라 검색 · 미리보기 · 내보내기 · 동기화 매핑이 단순하다 (`blockTextParts` · `boxKind` 헬퍼).
- 저장된 v1 · v2 노트는 열 때 구버전 형태로 로그를 재생한 뒤 v3로 바꾸고 원본을 `migration-vN` 백업으로 남긴다 (DATABASE 9.2).
- 동기화(P5)의 텍스트 콘텐츠 사상에 `role` 필드(LWW)가 하나 늘고, 제목 상자 한 줄 규칙은 normalize N9가 지킨다 (DATABASE 8.1 · SYNC 13.4).
- 한 블록 안에서 제목과 본문을 함께 쓰고 싶으면 내용 상자에서 제목1~3 줄을 쓴다.

## 검토한 대안

- v1 유지(문서 첫 줄 heading을 제목으로 해석) — 제목과 본문 경계가 모호하고, 제목만 크게 쓰는 상자를 만들 수 없음
- v2(한 블록에 제목 칸 + 본문 칸) — 몇 시간 구현했으나 사용자가 거절. 칸 사이 커서 이동 · 빈 칸 처리가 복잡하고 캔버스 배치와 겹치는 개념
