# ADR-0009: 동기화 단위는 노트당 Y.Doc 1개 + 워크스페이스 Y.Doc 1개

| 항목 | 내용 |
|---|---|
| 상태 | 승인 (2026-10-01, 설계 마무리 위임에 따라 추천안 채택) |
| 날짜 | 2026-10-01 |
| 결정자 | 곰탱이 (제안: 설계 문서 작성 시) |

## 맥락

사용자 전체를 Y.Doc 하나로 두면 모든 기기가 모든 노트를 받아야 하고 문서가 끝없이 커진다. 블록마다 문서를 두면 연결 · 메타데이터 오버헤드가 크다.

## 결정

노트 내용은 노트당 Y.Doc 1개(= SyncRoom 1개), 노트 바깥 메타(노트 목록 · 폴더 · 태그 · 휴지통 · 동기화 설정)는 사용자당 워크스페이스 Y.Doc 1개. 새 기기는 워크스페이스를 먼저 받아 목록을 그리고, 노트 내용은 열 때(또는 백그라운드로) 받는다.

## 결과

- 노트 이동 · 태그 변경은 워크스페이스 문서만 건드린다.
- 여러 노트에 걸친 원자적 변경(가져오기 일괄 되돌리기)은 노트 단위로 나뉘어 동기화된다 — 일시적 중간 상태가 다른 기기에 보일 수 있다.
- 태그는 Y.Map<tagId,true>로 합집합 병합된다.

## 검토한 대안

- 사용자당 단일 Y.Doc — 크기 · 초기 동기화 비용
- 블록당 Y.Doc — 연결 수 폭증
