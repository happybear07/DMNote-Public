# ADR-0010: 검색 · Q&A 근거 검색은 클라이언트 인덱스

| 항목 | 내용 |
|---|---|
| 상태 | 승인 (2026-10-01, 설계 마무리 위임에 따라 추천안 채택) |
| 날짜 | 2026-10-01 |
| 결정자 | 곰탱이 (제안: 설계 문서 작성 시) |

## 맥락

오프라인 검색이 필요하고(local-first), 서버에 노트 전문 인덱스를 두면 E2EE가 사실상 불가능해진다. Q&A(FR-116)는 관련 노트를 찾아 근거로 답해야 한다.

## 결정

검색 인덱스(BM25 + 한국어 음절 2-gram)를 search 워커에 두고 IndexedDB에 조각 단위로 영속한다. Q&A는 같은 인덱스로 상위 근거 조각을 찾아 그것만 프록시로 보낸다. 서버 측 임베딩 인덱스는 만들지 않는다.

## 결과

- 검색은 오프라인에서도 동작한다.
- 의미 검색(동의어 · 바꿔 말하기)은 약하다 — Q&A 근거 재현율 0.8 미달 시 기기 내 임베딩을 검토한다.
- 노트 수천 개 규모에서 인덱스 크기가 수십 MB가 될 수 있다.

## 검토한 대안

- 서버 임베딩 인덱스 — 개인정보 · E2EE 충돌 · 일정
- 형태소 분석기 — 사전 크기 · 워커 로드 시간
