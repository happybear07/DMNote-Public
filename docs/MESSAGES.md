## 1. 말투 · 목소리 가이드

### 1.1 해요체로 통일한다

**결정 — 모든 UI 문구는 해요체(-어요/-해요)로 쓴다. 다이얼로그 · 법적 고지 · 오류도 예외 없이.**

| 근거 | 설명 |
|---|---|
| 매일 여는 개인 도구 | DamianNote는 혼자 쓰는 노트앱이다. 합니다체는 공지 · 약관 · 은행 앱의 말투라 "시스템이 통보한다"는 거리감을 만든다. 해요체는 옆에서 알려 주는 말투다 |
| 오류 상황에서 덜 딱딱하다 | 저장 실패 · 충돌 · 키 오류처럼 불안한 순간에 "~하지 못했습니다"보다 "~하지 못했어요"가 덜 경고처럼 들린다. 이 제품의 오류 문구는 대부분 "그래도 데이터는 안전하다"를 전하는 문장이라 더 맞다 |
| 짧다 | 토스트는 한 줄이어야 한다. "저장했습니다"(5자) → "저장했어요"(5자)는 같지만, "확인하시기 바랍니다" → "확인해 주세요"처럼 대부분 해요체가 짧다 |
| 사용자 기대 | 노션 한국어판 · 국내 주요 생산성 · 금융 앱의 UI 문구가 해요체로 수렴했다. 노션 사용자를 데려오는 제품이 다른 말투를 쓸 이유가 없다 |
| 한 가지로만 | 섞어 쓰면 문구마다 작성자가 보인다. 예외를 두지 않는 것이 규칙을 지키기 쉽다 |

현재 구현에 남아 있는 합니다체 문구는 부록 A에서 교체한다.

### 1.2 다섯 가지 원칙

| # | 원칙 | 하지 말 것 | 이렇게 |
|---|---|---|---|
| P1 | **무엇이 안전한지 먼저 말한다.** 실패 문구에는 데이터 상태를 꼭 넣는다 | 저장에 실패했습니다. | 변경 내용을 저장하지 못했어요. 화면의 내용은 그대로 있어요. |
| P2 | **다음에 할 일을 말한다.** 버튼이 없으면 문장에, 있으면 버튼에 | 오류가 발생했습니다. | 잠시 후 다시 시도해 주세요. [다시 시도] |
| P3 | **탓하지 않는다.** 주어를 사용자로 두지 않는다 | 잘못된 API 키를 입력하셨습니다. | 이 키로는 Claude에 연결하지 못했어요. 키를 다시 확인해 주세요. |
| P4 | **짧게, 구체적으로.** 숫자 · 이름 · 시간을 넣는다 | 일부 항목이 처리되지 않았습니다. | 일부 항목은 형식이 맞지 않아 빼고 12개만 만들었어요. |
| P5 | **내부 용어를 쓰지 않는다.** | IndexedDB 쓰기 실패 (QuotaExceededError) | 저장 공간이 가득 찼어요. |

### 1.3 세부 규칙

- **길이** — 토스트 40자 이내 한 문장(두 문장까지 허용), 배너 80자 이내, 다이얼로그 제목 20자 이내 + 본문 3문장 이내.
- **안심 문장 고정형** — 데이터 상태를 말할 때는 아래 문장을 그대로 쓴다. 비슷한 변형을 만들지 않는다.
  - `노트는 이 기기에 안전하게 남아 있어요.` (로컬 데이터)
  - `원문은 그대로 있어요.` (AI · OCR 실패, 붙여넣은 원문)
  - `노트는 바뀌지 않았어요.` (취소 · 중단)
  - `되돌릴 수 없어요.` (영구 삭제 — 이 문장은 파괴적 동작에만)
- **버튼** — 동사로 끝낸다(`다시 시도` · `설정 열기` · `영구 삭제`). `확인` · `예` · `아니오`는 쓰지 않는다. 취소 버튼은 `취소`, 정보만 있는 다이얼로그의 닫기는 `닫기`.
- **파괴적 동작** — 버튼 이름에 무엇이 사라지는지 쓴다(`3개 영구 삭제`). 빨간색, 초기 포커스는 `취소`.
- **존댓말 수위** — "~하시겠습니까", "~해 주시기 바랍니다"를 쓰지 않는다. 부탁은 `~해 주세요`, 제안은 `~해 보세요`, 질문은 `~할까요?`.
- **문장 부호** — 느낌표 · 이모지 · 말줄임 남용 금지. 진행 중 상태에만 `…`(한 글자 말줄임표). 따옴표는 이름을 감쌀 때 작은따옴표 `'노트 제목'`.
- **변수와 조사** — 변수 바로 뒤에 조사를 붙이지 않는다. `'{title}'을(를)` 대신 `'{title}' 노트를`처럼 명사를 끼운다. 숫자는 `{n}개`.
- **오류 코드** — 본문에 HTTP 코드 · 내부 코드를 쓰지 않는다. 지원 문의용 요청 ID(`X-Request-Id`)는 `오류 정보 복사` 버튼으로만 준다.
- **시간 표시** — 1분 미만 `잠시`, 1시간 미만 `{m}분`, 그 이상은 `오후 3:20`처럼 시각. 날짜는 `10월 28일`.

## 2. 유형 정의 · 작성 규칙

| 유형 | 위치 | 사라짐 | 쓰는 경우 | 등급 (ARCHITECTURE 10) |
|---|---|---|---|---|
| toast | 하단 중앙, 도구 막대 위 | 4초. 버튼이 있으면 6초, 포커스 · 호버 중에는 멈춤 | 동작 결과 · 재시도 가능한 실패 | 토스트 |
| banner | 캔버스(또는 본문) 상단 띠 | 원인이 풀리면 자동. 닫기 가능 여부는 행마다 명시 | 기능이 제한된 상태가 이어질 때 | 배너 |
| dialog | 화면 중앙 모달 | 버튼으로만 | 결정이 필요하거나 데이터 위험 | 차단 다이얼로그 |
| inline | 컨트롤 옆 · 상태 표시 · 툴팁 · 패널 안 | 상태에 따라 | 상태 라벨 · 입력 검증 · 화면 안 안내 | — |
| empty | 비어 있는 화면 · 목록 중앙 | 내용이 생기면 | 빈 상태 | — |
| placeholder | 입력 필드 · 빈 줄 | 입력하면 | 입력 힌트 | — |

- 토스트는 한 번에 하나만 보인다. 새 토스트가 오면 앞의 것을 바로 교체하되, 버튼 있는 토스트(실행 취소 등)는 교체 전에 최소 2초를 보장한다.
- 같은 배너는 한 번에 하나. 배너가 여럿이면 데이터 위험 > 연결 > 안내 순으로 하나만 보이고 나머지는 `+{n}`.
- 스크린리더: toast · inline 상태는 `aria-live="polite"`, 데이터 위험 dialog는 `role="alertdialog"`(UX-FLOW 8절 A4).
- 문구 안 `{…}`는 변수, `[…]`는 버튼, `〈…〉`는 링크다.
